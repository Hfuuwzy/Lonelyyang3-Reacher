# DeepSeek Harness Provider Routes and Protocols

**Evidence date:** 2026-09-24

## Built-In Routes

The official model guide lists `openai` and `anthropic` among the provider IDs supplied by dsh and says the installed catalog supplies each built-in provider’s endpoint, protocol, and model list. The package reference gives matching route-keyed examples (`openai` and `anthropic`) and per-provider credential references. Thus users can add these catalog routes without declaring a wire protocol by hand; in the provider builder, a catalog route with no `api` reuses its catalog provider and model behavior. ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/user/guide/providers.md#L15-L19), [configuration example](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L40-L58), [provider builder](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/src/provider.ts#L167-L176))

“Built-in” does not mean that OpenAI or Anthropic is the preselected/default route. The shared base profile selects `deepseek-official` / `deepseek-flash`; it mounts `llm-pi-ai` dormant with zero routes until its provider settings section is populated. The guide describes adding a catalog provider through the Models UI. ([base profile defaults](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/bundle/base/cordis.patch.yml#L80-L86), [dormant adapter row](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/bundle/base/cordis.patch.yml#L120-L128), [provider guide](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/user/guide/providers.md#L15-L19))

When a built-in catalog route is pointed at a gateway with `baseURL`, its catalog endpoint can be replaced while the catalog protocol remains in effect if `api` is omitted. The protocol builder also permits an explicit `api` override, but that is distinct from the route’s ordinary catalog-backed default. ([field defaults](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L75-L81), [provider construction](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/src/provider.ts#L167-L190))

## Custom and Self-Hosted Endpoints

The Web guide explicitly names company gateways, relays, and self-hosted servers. Its form asks for a lowercase provider ID, base URL, protocol, credential, and at least one model. In profile configuration the row is `llm-pi-ai`, with a `providers` mapping keyed by the route ID. A route absent from the installed catalog must supply `api`, `baseURL`, and a non-empty `models` list. ([guide](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/user/guide/providers.md#L21-L27), [custom route example](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L59-L73), [serviceability requirement](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L111-L117))

Example profile patch for a local OpenAI Chat Completions-compatible server:

```yaml
- id: llm-pi-ai
  name: '@deepseek-ai/dsh-llm-pi-ai'
  config:
    providers:
      local-vllm:
        apiKeyEnv: LOCAL_LLM_API_KEY
        api: openai-completions
        baseURL: http://127.0.0.1:8000/v1
        models:
          - id: local-model
```

The route’s protocol is route-wide, not selected independently per model; a gateway serving two protocols needs two route IDs. A key reference is optional in file configuration, but unauthenticated operation is protocol-dependent: the reference specifically warns that pi-ai’s OpenAI-compatible implementation still needs an API key or an `Authorization` header. ([one-protocol guide](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/user/guide/providers.md#L21-L23), [keyless and route limitations](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L38-L38), [auth caveat](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L225-L227))

For the standard Web UI, the pinned repository guide says the profile configuration is `$DSH_HOME/profiles/<profile>/cordis.patch.yml` (the default `dsh web` profile is `web`). The Models page writes that same patch. ([pinned guide](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/user/guide/providers.md#L41-L48))

## Protocols and Scope

The current `llm-pi-ai` implementation has exactly this explicit protocol table for hand-declared routes:

| Configuration value | Protocol named in the official guide | Available for custom route? |
|---|---|---|
| `openai-completions` | OpenAI Chat Completions | Yes |
| `openai-responses` | OpenAI Responses API | Yes |
| `anthropic-messages` | Anthropic Messages API | Yes |

The table maps those identifiers to the corresponding pi-ai API implementations. `supportedProtocols()` returns its keys, and the guide says the same three choices appear in the custom model API form. ([implementation](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/src/provider.ts#L47-L63), [UI/config guide](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/user/guide/providers.md#L21-L23))

The three-value limit applies to **explicit custom-route configuration**, not every protocol the installed catalog can reach. The implementation deliberately reuses a catalog provider when no override is supplied and states that catalog providers retain their own implementations; the source says an explicit override not present in its table is rejected. Conversely, a configured `api` is applied to every model on that route. ([provider implementation](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/src/provider.ts#L29-L45), [route selection](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/src/provider.ts#L167-L190), [single-protocol limitation](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L223-L227))

The dedicated `dsh-llm-deepseek` adapter is a separate case: it uses the Messages API, defaults its root to `https://api.deepseek.com/anthropic`, accepts a Messages-compatible custom `baseURL`, and rejects a `protocol` setting. It is not the way to send Chat Completions to a self-hosted DeepSeek model; use a `llm-pi-ai` custom route with the matching protocol instead. ([adapter reference](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/README.md#L10-L12), [endpoint and protocol constraints](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/README.md#L78-L83), [config rejection](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/src/config.ts#L213-L216))

## Credential Semantics

For `deepseek-official`, the direct adapter’s config defaults `apiKeyEnv` to `DEEPSEEK_API_KEY`. The source explicitly says a missing key is resolved at request time and causes `MISSING_CREDENTIAL`, not plugin-load failure. The request path first asks the optional DeepSeek account integration for an eligible token; if it returns none, it resolves the API key through the Harness credential service or launching environment. If neither is available, that DeepSeek model request fails. ([default reference and config schema](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/src/config.ts#L20-L30), [schema default](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/src/config.ts#L92-L96), [per-request key lookup](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/src/index.ts#L64-L85), [account-token fallback](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/src/index.ts#L89-L95), [request selection](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/src/adapter.ts#L83-L88))

Therefore, a DeepSeek credential is a runtime requirement **for an actual call through the direct DeepSeek route**, but not a global dependency for loading or using dsh with a different provider. This distinction is visible in the shipped minimal SDK profile, which explicitly configures the DeepSeek adapter with `apiKeyEnv: DEEPSEEK_API_KEY`, and in the base profile, which defaults agents to `deepseek-official` while also mounting the pi-ai route adapter for user configuration. The README’s minimal adapter example likewise labels the key as a per-request credential reference. ([SDK profile](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/bundle/sdk-minimal/cordis.patch.yml#L1-L3), [SDK DeepSeek row](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/bundle/sdk-minimal/cordis.patch.yml#L26-L31), [base default and alternate adapter](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/bundle/base/cordis.patch.yml#L80-L86), [pi-ai mount](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/bundle/base/cordis.patch.yml#L120-L128), [direct adapter example](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-deepseek/README.md#L36-L48))

One scope caveat: the shared base composition separately configures its DeepSeek-backed `web-search-deepseek` feature with the same `DEEPSEEK_API_KEY`. That is an auxiliary search route, not evidence that OpenAI or Anthropic model calls require a DeepSeek key; using that separate search feature can still require its own DeepSeek credential. ([base search configuration](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/bundle/base/cordis.patch.yml#L462-L480))

For pi-ai routes, `apiKeyEnv` is optional in file configuration; omitting it defers a catalog provider to its ambient auth discovery. A **named but unresolved** credential reference is different: it fails with `MISSING_CREDENTIAL`. For a custom OpenAI-compatible endpoint, the protocol itself may still require a key or an `Authorization` header. ([credential rules](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L36-L38), [auth limitation](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/packages/llm/llm-pi-ai/README.md#L225-L227))

## Custom Plugin Composition

The three-protocol table describes the shipped `llm-pi-ai` configuration surface; it is not a Harness-wide ceiling. The official adapter cookbook shows a new plugin extending `LlmAdapter`, implementing `stream()` to translate the provider API, then registering its own provider route with `ctx.llm.registerAdapter()`. The architecture docs describe the model adapter as a replaceable plugin and profile patches as a way to add or replace plugin rows. **Inference:** a developer can support another wire protocol by implementing and composing such an adapter; this is custom code, not a protocol option built into the route form or the three-entry `llm-pi-ai` table. ([adapter cookbook](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/cookbook/adding-an-llm-adapter.md#L5-L23), [adapter contract](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/cookbook/adding-an-llm-adapter.md#L25-L35), [plugin composition](https://github.com/deepseek-ai/deepseek-harness/blob/46a7f68b0922371ce7144b668b90e377d8e799f4/docs/architecture.md#L11-L27))
